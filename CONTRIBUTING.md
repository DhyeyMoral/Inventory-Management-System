# Contributing Guide

Thank you for contributing to the Inventory Management System.

## Development Workflow

1. Create a branch from `main`.
2. Use a descriptive branch name.
3. Make focused changes related to one task.
4. Validate the affected HTML, CSS, JavaScript, and documentation before opening a pull request.
5. Open a pull request against `main`.
6. Describe what changed and how it was validated.

## Branch Naming Convention

Use one of the following patterns:

- `feature/<short-description>` — new functionality
- `fix/<short-description>` — bug fixes
- `docs/<short-description>` — documentation changes
- `refactor/<short-description>` — code restructuring

Example:

```text
docs/improve-readme
```

## Commit Convention

Use a short, descriptive commit message with a conventional prefix:

- `feat:` — new functionality
- `fix:` — bug fix
- `docs:` — documentation
- `style:` — formatting or non-functional style changes
- `refactor:` — code restructuring
- `test:` — tests or validation
- `chore:` — maintenance

Example:

```text
docs: add contribution guidelines
```

## Documentation Guidelines

- Keep instructions clear and reproducible.
- Update the README when project setup or usage changes.
- Keep file and folder names consistent with the repository.
- Do not document features that are not present in the project.

## Code Guidelines

- Keep HTML structure readable and properly organized.
- Keep CSS rules in the appropriate stylesheet.
- Keep JavaScript validation logic in the existing validation directory where applicable.
- Avoid unrelated changes in the same pull request.

## Validation Before a Pull Request

Before opening a pull request:

- Open the relevant HTML pages in a browser.
- Check navigation and links.
- Check forms and JavaScript validation where applicable.
- Confirm that documentation paths and instructions are correct.
- Review the changed files before submitting the pull request.

## Pull Request Guidelines

A pull request should:

- Have a clear title.
- Explain the purpose of the change.
- List important files or areas changed.
- Mention validation performed.
- Keep the scope focused.

## Issue Guidelines

Use the repository's issue templates for:

- Bug reports
- Feature requests

Provide clear steps, expected behavior, and relevant context.
